# 生成可导入的思维导图文件（mindmap-import）

## 0. 这份技能解决什么

any-version 的思维导图有四种建图方式：AI 项目导入、AI 文本导入、右栏 Agent 对话、手动加节点。
它们都**要起 AI 或要人点**。当外部已经有一个「知道内容」的 Agent（Codex / Claude Code / 脚本 / 另一个会话）时，
最省事的路径是：**它直接产出一份符合格式的 JSON，用户一键导入**——不烧 token、结果可复现、可进版本库。

导入入口：`mm_import_nodes`（后端），前端在思维导图面板左栏底部的「导入 JSON 文件」。
本技能只关心**怎么把文件写对**；导入能力本身属于 mindmap 模块，不在本技能范围。

## 1. 文件长什么样（最小可用）

```json
{
  "name": "订单系统",
  "nodes": [
    { "id": "root", "name": "订单系统", "kind": "root", "detail": "整套下单-支付-履约流程的总览" },
    { "id": "a", "name": "下单", "parent_id": "root", "kind": "module", "detail": "购物车校验 → 库存锁定 → 生成订单" },
    { "id": "b", "name": "支付", "parent_id": "a", "kind": "service", "detail": "对接三方支付，含超时关单补偿" }
  ]
}
```

顶层可带：`name` / `description` / `layoutDir`（`lr` 左→右 默认、`rl`、`tb`、`bt`）+ 必填的 `nodes`。

## 2. 节点字段（完整表见 `references/schema.md`）

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | 否 | 本文件内唯一、稳定、短（如 `a1`）。不填会按序号自动补。**子节点靠它引用父级** |
| `name` | 否（强烈建议） | 节点标题。**只放标题**，不写长句 |
| `parent_id` | 否 | 父节点 id（也接受 `parentId`）。**不填或引用了不存在的 id = 成为一条新的主线** |
| `detail` | 否（强烈建议） | 说明正文，可 Markdown。旧的 `description` 也认 |
| `kind` | 否 | 12 选 1，越界会被改成 `other` |
| `color` | 否 | `#RRGGBB`；不填按序号取调色板；非法值改 `#94a3b8` |
| `sources` | 否 | 证据文件（项目相对路径），去重、限 6 个 |

`kind` 白名单：`root` `module` `component` `service` `route` `config` `file` `task` `requirement` `constraint` `risk` `other`。

## 3. 生成流程（三类输入）

### 3.1 一段话 / 一段需求

1. 找出**中心主题** → 一条 `kind: "root"` 的根
2. 按语义拆 3～7 条主线（`module` / `requirement` / `task`…）
3. 每条主线再往下 1～2 层，直到「再拆就是句子」为止
4. 把原文里被拆散的**说明性文字放进 `detail`**，不要塞进 `name`

### 3.2 一个项目（代码仓库）

1. 先看清**真实结构**：入口、目录分层、配置、数据流，不要按想象的架构写
2. 根 = 项目名；主线 = 顶层模块 / 子系统；往下 = 关键文件、服务、路由
3. 每个节点尽量带 `sources`（相对路径），让节点能锚到真实文件
4. 不确定归属的放 `other`，**不要为了填满而编造模块**

### 3.3 一个文件（文档 / 会议纪要 / 设计说明）

1. 按**原文层级**展开，不要合并层级（原文有四级就输出四级）
2. 标题进 `name`，标题下的正文进 `detail`
3. 原文是编号层级（`一、` / `（一）` / `1.` / `1.1` / `①`）时，**一级不落**

通用要求：
- 每层 3～7 个节点，最多不超过 12；总层数建议 ≤ 4（深了在画布上读不了）
- `name` ≤ 20 字；长解释一律进 `detail`
- 节点之间**只用 `parent_id` 表达树关系**；不要试图表达交叉引用（本格式不支持）

## 4. 自检（必做）

```bash
python .agents/skills/mindmap-import/scripts/validate.py <file.json>
```

脚本会报：JSON 是否合法、`nodes` 是否为空、id 重复、`parent_id` 悬空（会被当成新主线）、`kind` 越界、`color` 非法、`name` 为空、层级是否过深。
**报错项修完再交付**；warning 可以保留但要跟用户说明。

## 5. 交付

- 落盘命名：`<主题>.mindmap.json`（放项目根目录或 `.any-version/` 下均可，告诉用户路径）
- 回复里给出：文件路径 + 节点数 + 层级深度 + 导入方式（any-version → 思维导图 → 左栏底部「导入 JSON 文件」）
- 导入方式由用户在应用内选（选中文件后弹「导入到哪？」）：
  - **新建一张导图**（推荐）
  - **追加到《当前文档》** —— 保留原有节点，把导入内容挂上去（多条主线会并存）
  - **替换《当前文档》的全部内容** —— 先清空再写入，会再弹一次红色确认（不可撤销）
- 没有打开任何文档时不会弹选择框，直接新建

## 6. 常见错误（踩过的坑）

1. **子节点引用了不存在的 `parent_id`** → 静默变成另一条主线，图看着像"少了一半"。生成后务必跑校验
2. **把整段说明写进 `name`** → 画布上节点名撑爆、完全不可读
3. **`kind` 自造值**（如 `database`、`api`）→ 被改成 `other`，语义丢失，用白名单里最接近的
4. **id 用了中文或带空格** → 虽能导入但不稳定，用 `a1` / `mod-order` 这类短 id
5. **给 JSON 套 Markdown 代码围栏** —— 导入端能剥，但**不要依赖它**，直接输出纯 JSON
6. **一次塞几百个节点** → 画布无法阅读；先出主干，细节靠 `detail` 承载
